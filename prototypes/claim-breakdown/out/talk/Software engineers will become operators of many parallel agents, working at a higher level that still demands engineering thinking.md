Ayush Parikh argues that the job of a software engineer is shifting from writing code by hand to running several AI agents at once, each on a different task or work stream. The engineer builds the automations and tools around those agents, reviews what they produce, and guards quality with style guides, tests and flags. The work gets more zoomed out, but it is still engineering: judgment, data and critical thinking. He says humans are still needed to build great products, and that the fundamentals still matter because agents make mistakes.

## Claims

### Engineers will spend their time operating agents, not writing every line themselves
- "The future of engineering and software engineering is that you are building automations, you are building integrations, you are, building at this higher level of operating your agents to work effectively for you, to work on different projects, different work streams, different features." — Ayush Parikh, [[AI301 Live Class]], ≈1:45:14
- "think of yourself as sort of like a conductor of [sorts]" — Ayush Parikh, [[AI301 Live Class]], ≈1:45:14

### Engineers must manage several agent sessions at once, with tools and workflows tailored to them
- "you're gonna have to get used to basically managing multiple agent sessions at a time. Often three, four, five agent sessions at a time." — Ayush Parikh, [[AI301 Live Class]], ≈1:46:18
- "your workflow needs to be tailored to you" — Ayush Parikh, [[AI301 Live Class]], ≈1:45:46

### Quality comes from guardrails around agent-written code, so humans can review at a higher level
- "you build good guards around the code that you've written, right?" — Ayush Parikh, [[AI301 Live Class]], ≈1:46:49
- "Writing good tests to make sure things don't break on critical paths, especially, and having your agent flag things … for you to review" — Ayush Parikh, [[AI301 Live Class]], ≈1:47:19

### The higher-level work is still engineering thinking, and conversations with peers shift from code to design decisions
